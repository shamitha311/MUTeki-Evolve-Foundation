# MUTeki-Evolve

Foundation contracts and deterministic mocks for a safe, iterative security-investigation strategy system.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 5000)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string
- `uv sync --extra dev && uv run pytest` — run the Python contract and mock tests
- `uv run python -c "import asyncio; from orchestration.mock_scenario import run_three_round_scenario; print(asyncio.run(run_three_round_scenario()))"` — run the deterministic three-round fixture

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Python 3.10+ contract layer with Pydantic and pytest

## Where things live

 - `app/models/` — project-owned SandboxTarget, Strategy, event, evidence, result, and score contracts
 - `app/validation.py` — fail-closed target and generated-strategy validation
 - `muteki_adapter/` — semantic adapter protocol and deterministic development mock
 - `orchestration/mock_scenario.py` — three-round fixture for downstream chunks
 - `vendor/muteki/`, `vendor/mtasa/` — immutable upstream source snapshots
 - `docs/INTEGRATION_CONTRACT.md` — cross-chunk contract source of truth
 - `docs/UPSTREAM_NOTES.md` — verified upstream behavior and explicit gaps

## Architecture decisions

- Muteki owns execution; application strategies express high-level intent only.
- Trusted target selection belongs to orchestration and is never generated by the strategy engine.
- Upstream events are normalized into project-owned models rather than exposed to later layers.
- Real Muteki integration, scoring, strategy evolution, orchestration, and full UI remain deferred to later chunks.

## Product

The current foundation is developer-facing: it gives later chunks strict shared contracts, safe validation boundaries, and deterministic mocks without requiring a live Muteki worker runtime.

## Gotchas

- Do not edit files under `vendor/muteki` or `vendor/mtasa`.
- Do not add arbitrary command execution, host execution, a second executor, or a second sandbox.
- `progress_score` is not a solved percentage; scoring is a later-chunk concern.
